# 실제 기기 확인

이 문서의 항목은 수동 검증 계획입니다. 자동 테스트 통과나 빌드 성공이 실제 입력 차단 성공을 의미하지 않습니다.

## 시작과 해제 확인

- **청소 시작**이 기본 시작 버튼으로 표시되는지 확인합니다.
- 청소 중 종료 버튼이 **청소 끝내기** 하나만 표시되고, 코드나 별도 해제 버튼이 없는지 확인합니다.
- 몇 개의 키를 눌러 차단을 확인한 뒤 손을 떼고 **청소 끝내기**를 눌러 즉시 대기 화면으로 돌아오는지 확인합니다.
- 창 높이를 줄이거나 본문을 스크롤해도 하단 버튼이 보이고 클릭되는지 확인합니다.
- 아래 항목을 검사하기 전에 마우스로 앱을 닫거나 강제 종료하는 경로를 확인합니다. Mac에서는 다른 앱을 선택한 뒤  → 강제 종료 → Keyboard Saver를 사용합니다.

## macOS

- 권한 미허용 상태에서 시작 버튼 대신 권한 안내가 표시되는지 확인.
- 손쉬운 사용 권한 허용 후 앱으로 돌아왔을 때 상태가 갱신되는지 확인.
- 권한 요청 응답이 처리 중일 때 앱으로 돌아와도 이후 상태를 다시 읽는지 확인.
- **허용했는데도 안 되나요? → 현재 앱을 Finder에서 보기**가 실제 실행 중인 `.app`을 선택하는지 확인. 이 과정에서 입력 차단은 시작되지 않아야 함.
- Debug의 이름·식별자가 Release와 다르고, 각각 정확한 앱을 손쉬운 사용에 등록할 수 있는지 확인.
- Cursor 등의 내장 터미널에서 Debug 앱을 종료한 뒤 `bash tool/dev_macos.sh --no-build`로 실행하여 기존 앱 권한이 인식되는지 확인. 연결된 터미널에서 `r`을 눌러 핫 리로드 후에도 권한 상태가 유지되는지 확인.
- 재빌드 후 권한이 인정되지 않으면 기존 항목 삭제 → 현재 앱 다시 추가 → 다시 확인 순서로 복구되는지 확인. ad hoc 서명에서는 재빌드 간 권한 유지가 보장되지 않음.
- 메모장 등 버려도 되는 문서를 열고 청소 모드를 시작. 앱을 전환해 일반 문자, 숫자, Enter, Escape, Delete, 방향키가 문서에 전달되지 않는지 확인.
- Command/Control/Option/Shift 및 좌우 modifier 조합으로 앱 전환·종료·붙여넣기가 실행되지 않는지 확인.
- 키를 하나 누른 상태에서 시작하면 시작이 거절되는지 확인.
- 긴 키 반복과 여러 키를 동시에 누르는 청소 동작으로 해제되지 않는지 확인.
- 한글/영문 입력기에서 임의의 숫자열을 입력하거나 숫자패드를 눌러도 청소 모드가 유지되는지 확인.
- 버려도 되는 문서에서 키를 누른 상태로 **청소 끝내기**를 눌러도 대기 없이 종료되는지 확인. 종료 이후에는 입력이 다시 전달되므로 평소에는 키에서 손을 떼고 버튼을 누름.
- 마우스 해제 후 모든 modifier가 정상 동작하는지 확인. Caps Lock과 Fn은 별도로 검사.
- 앱 창 닫기, Dock의 종료, 잠자기, 화면 잠금 및 사용자 전환 후 키보드 사용이 복구되는지 확인.
- 권한 취소 또는 event tap 비활성화 시 성공 화면이 유지되지 않는지 확인.
- 내장/USB/Bluetooth 키보드, 둘 이상의 키보드, 외부 키보드 연결 해제 상황에서 해제 경로 확인.
- 청소 전 밝기·음량 수준과 재생/일시정지 상태를 확인하고, 청소 중 밝기 올림/내림·음량 올림/내림·음소거·재생/일시정지를 눌러 값과 재생 상태가 유지되는지 확인. 일시정지 상태와 재생 중 상태에서 각각 확인.
- 이전/다음 곡, 길게 눌러 탐색, 키보드 조명 조절도 확인. 반복 입력 및 Option/Shift 조합에서도 설정 창이나 시스템 표시가 뜨지 않는지 확인.
- 특수 키가 눌려 있거나 외장 키보드를 분리해 키 해제 이벤트가 오지 않아도 **청소 끝내기**가 바로 동작하는지 확인.
- 청소가 끝난 뒤 밝기·음량·재생 키가 정상 동작하고, 마우스 보조 버튼과 스크롤도 계속 동작하는지 확인.
- Fn으로 전환한 F1–F12, 내장/외장 키보드별 특수 키, Touch ID, 전원, 보안 입력 활성 상태의 지원 범위를 기록. 하드웨어 강제 종료 시험은 하지 않음.

## Windows

- Windows에서 먼저 `flutter build windows --release`를 실행.
- 일반 사용자 권한으로 실행하고 일반 문자, 시스템 단축키, 좌우 modifier, 키 반복 및 동시 입력 차단을 확인.
- 표준 음량·음소거·재생/일시정지·이전/다음 곡 키의 누름·뗌·반복이 차단되고, **청소 끝내기**로 대기 없이 종료되는지 확인.
- 밝기 키는 HID/제조사 경로에 따라 키보드 훅을 거치지 않을 수 있으므로 별도 기록. 현재 Windows 밝기 차단은 보장하지 않음.
- 숫자열과 숫자패드 입력으로 청소 모드가 끝나지 않는지 확인. 키를 누른 채 마우스 해제를 요청해도 바로 종료되는지 확인.
- 화면 잠금, 사용자 전환, 절전 및 앱 종료 이후 입력 복구를 확인.
- 관리자 권한 앱, UAC 및 보안 데스크톱은 일반 데스크톱과 따로 검사. Ctrl+Alt+Delete는 차단 대상으로 보장하지 않음.
- CPU 부하와 장시간 청소 세션에서 훅이 유지되는지 확인. Windows는 시간 초과된 low-level hook을 별도 알림 없이 제거할 수 있음.

## 기록

각 검사에 OS 버전, CPU 아키텍처, 키보드 종류/배열, 입력기, Debug/Release 여부를 함께 기록합니다. 자동 테스트에서는 실제 전역 입력 차단을 켜지 않습니다.

현재 자동 검증은 macOS 시스템 키 판정·상태 전환·채널 계약·화면 동작을 다룹니다. 위 기기별 입력 차단 검사는 별도 수행이 필요합니다.
